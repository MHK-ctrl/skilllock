# skilllock

**Pin Git-hosted Agent Skills to an immutable commit and reproduce them on demand.**

`skilllock` is a local, deterministic lockfile manager for Agent Skills. You
declare where a skill lives in `skills.toml`; `skilllock lock` resolves each
declared ref to a full commit and records a sha256 digest for every file;
`skilllock sync` fetches those pinned commits and installs them; `skilllock
verify` checks installed files against the lock without touching the network.

It is deliberately offline-first: **no LLM, no API key, no registry, no
server.** Retrieval fetches into a throwaway bare repository and reads objects
with `git archive`, so no working tree is ever checked out and no repository
hook, filter, or script is ever executed.

## Usage

```bash
uv sync --locked
uv run skilllock init
uv run skilllock add https://github.com/example/agent-skills.git --name code-review --ref refs/tags/v1.2.0 --subdir skills/code-review
uv run skilllock lock
uv run skilllock sync --target ./skills
uv run skilllock verify --target ./skills
```

`--target` defaults to `./skills`. There is no `--force` flag and no option
that executes repository content. `skilllock init` refuses to overwrite an
existing `skills.toml`.

### `skills.toml`

```toml
format = 1

[[skill]]
name = "code-review"
source = "https://github.com/example/agent-skills.git"
ref = "refs/tags/v1.2.0"
subdir = "skills/code-review"
```

Rules: `name` is 1–64 lowercase letters/digits with single hyphens and must be
unique; `source` is `https://github.com/OWNER/REPO` with an optional `.git`;
`ref` is a full `refs/heads/...` or `refs/tags/...` ref validated with
`git check-ref-format`; `subdir` is an optional repository-relative POSIX path
(default `.`). Unknown keys and unsupported format versions are rejected.

### `skills.lock`

Generated by `skilllock lock`; never hand-edited.

```toml
format = 1

[[skill]]
name = "code-review"
source = "https://github.com/example/agent-skills.git"
ref = "refs/tags/v1.2.0"
subdir = "skills/code-review"
commit = "0123456789abcdef0123456789abcdef01234567"

[[skill.files]]
path = "SKILL.md"
sha256 = "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
mode = "100644"
```

`commit` is a full 40-character lowercase SHA. `mode` is Git's regular-file
mode (`100644` or `100755`); symlink and submodule modes are forbidden. File
records are sorted by UTF-8 path bytes. There is no aggregate tree hash.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success; `verify` reports no drift. |
| `1` | A deterministic validation finding (a check ID) or drift was reported. |
| `2` | Invalid usage, filesystem, Git/network, or other operational failure. |

Operational fetch problems (DNS, TLS, timeout, permissions) return `2`.
Malformed or inconsistent manifest/lock data returns `1`.

## Check IDs

All checks are errors in v0.1.

| ID | Triggers when |
| --- | --- |
| `SL001` | TOML cannot be parsed, the format version is unsupported, a required key is missing, an unknown key is present, or a field has the wrong type. |
| `SL002` | Skill name is invalid or duplicated; source URL, ref syntax, or `subdir` is invalid. |
| `SL003` | A locked commit is missing/malformed, does not resolve to a commit, or disagrees with the manifest/lock entry. |
| `SL004` | An installed file is missing, extra, has different bytes/hash, or a different executable mode. |
| `SL005` | An unsafe path, traversal, symlink, unsupported archive object, or platform-colliding path is detected. |
| `SL006` | The snapshot lacks a regular root-level `SKILL.md`, or its frontmatter `name` is missing/invalid/does not equal the manifest `name`. |

## Limitations

- **Hashes are not a trust or security guarantee.** A matching digest only shows
  that the bytes equal the bytes pinned in the lock. It says nothing about who
  published them, whether the skill is safe, or whether you should run it.
- **v0.1 supports Git sources only**, restricted to `https://github.com` URLs.
  There are no transitive dependencies, private registries, or submodules.
- **`verify` is offline.** It checks installed files against `skills.lock` and
  never contacts a remote, so it cannot detect upstream changes.
- **`skilllock` never executes skills.** It fetches, hashes, and copies files.
  It does not run scripts, hooks, installers, or any repository content.
- `skilllock` is not an LLM-based security scanner and does not answer "is this
  skill safe?".
